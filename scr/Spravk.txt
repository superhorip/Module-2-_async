. logging.basicConfig() — настройка логирования
Определяет, какие сообщения показывать и как они должны выглядеть.
import logginglogging.basicConfig(    level=logging.INFO,    format="%(asctime)s | %(levelname)s | %(message)s")



Здесь:
- level=logging.INFO — минимальный уровень сообщений, которые будут отображаться.
- %(asctime)s — дата и время события.
- %(levelname)s — уровень сообщения.
- %(message)s — сам текст.
Например, результат будет выглядеть так:
2026-11-20 14:30:00 | INFO | Началась загрузка страницы


basicConfig() обычно вызывается один раз при запуске программы, а не внутри каждого метода класса.
2. logging.getLogger() — создание логгера
logger = logging.getLogger(__name__)



Возвращает объект логгера, через который ты будешь записывать сообщения.

__name__ — специальная переменная Python, содержащая имя текущего модуля.

Например, если файл называется AsyncCrawler.py, логгер получит имя AsyncCrawler.

Это удобно, когда проект состоит из нескольких файлов: можно понимать, какой модуль записал сообщение.

Повторный вызов getLogger() с тем же именем возвращает тот же объект логгера.
3. logger.info() — информационные сообщения
Используется для обычных событий, когда программа работает нормально.
logger.info("Начинаем загрузку %s", url)



Например:
INFO | Начинаем загрузку https://example.com


В твоём краулере info() пригодится для регистрации начала и успешного завершения HTTP-запроса.
4. logger.error() — сообщения об ошибках
Используется, когда операция завершилась ошибкой.
logger.error("Не удалось загрузить %s", url)



Результат:
ERROR | Не удалось загрузить https://example.com


Важно: logger.error() только записывает сообщение. Он не останавливает программу и не обрабатывает исключение вместо try/except.
5. logger.exception() — логирование исключений
Похож на logger.error(), но дополнительно записывает traceback — цепочку вызовов, по которой можно определить место возникновения ошибки.

Пример:
try:    result = 10 / 0except ZeroDivisionError:    logger.exception("Ошибка вычисления")



Результат:
ERROR | Ошибка вычисления
Traceback (most recent call last):
  File "main.py", line 2, in <module>
    result = 10 / 0
ZeroDivisionError: division by zero


Используй logger.exception() внутри except, когда нужно сохранить подробную информацию об исключении.
6. Чем error() отличается от exception()?
Метод	Сообщение	Traceback
logger.error()	Да	Нет, по умолчанию
logger.exception()	Да	Да

Технически logger.exception() — это вызов логирования уровня ERROR с включённым exc_info=True.

Как это применить в твоём краулере
Тебе достаточно такой организации:
- В демонстрационном скрипте — один раз вызвать logging.basicConfig().
- В модуле AsyncCrawler — получить логгер через logging.getLogger(__name__).
- В fetch_url() — вызывать logger.info() при начале и успешном завершении запроса, а при ошибках — logger.error() или logger.exception().
И ещё один полезный момент: logger.info() и другие методы — обычные синхронные методы. Перед ними не нужен await, даже если ты вызываешь их внутри async def.

Для первого дня этого функционала logging тебе вполне достаточно.
